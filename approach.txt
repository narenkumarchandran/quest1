Hybrid Video Dialogue Detection Pipeline
==========================================

1. Overview
-----------
This system implements an efficient "Audio-First" phased architecture to identify the exact frame where a specific target dialogue appears in an online video (e.g., YouTube). It is designed to handle multiple sources of dialogue without downloading entire video files unless strictly necessary:
- Embedded/External subtitles (.srt, .vtt)
- Spoken dialogue (ASR via Whisper)
- Burned-in text / Scene text (OCR via EasyOCR)

2. Phased Architecture
----------------------
The pipeline drastically reduces network bandwidth and processing time by following a strict fallback chain:

1. Subtitle Search (Fastest): `yt-dlp` is used to fetch only the subtitle files. If a match is found, we immediately get a candidate timestamp.
2. Audio-First Fallback (Whisper): If no subtitles exist or match, only the audio track is downloaded. GPU-accelerated `faster-whisper` transcribes the audio to find a candidate timestamp.
3. Targeted Segment Download & OCR Fusion: Once a candidate timestamp is found via Audio or Subtitles, the system downloads only a short 20-second video clip (±10 seconds around the candidate) rather than the entire video. OCR scans this short segment to verify if the text visually appears on-screen (Fusion method).
4. Full Video Coarse OCR (Last Resort): If the target is not found in audio (e.g., it is purely a visual sign or on-screen text with no spoken equivalent), the pipeline falls back to downloading the full video and running a coarse 1 FPS OCR scan.

3. Matching Strategy
--------------------
String matching is handled by `RapidFuzz` using a weighted blend of `token_set_ratio` and `partial_ratio`. This approach is robust to OCR noise, Whisper word-flips, and partial text reveals, ensuring that minor spelling differences or added punctuation do not break the pipeline.

4. Frame Refinement & Mathematical Fallback
-------------------------------------------
"The exact frame is defined as the earliest frame the complete dialogue appears, or the start frame of the spoken utterance."

- Visual Text: If the text is on-screen, a temporal refinement step analyzes the ±2 second window at full FPS to lock onto the exact frame the text appears.
- Spoken Dialogue (No OCR Match): If the dialogue is spoken but not physically written on-screen (or OCR is skipped), the pipeline uses a Mathematical Fallback. It fetches the video's FPS and calculates the exact start frame using `int(timestamp_in_seconds * FPS)`.

5. Output Format
----------------
The pipeline outputs a clean JSON file containing:
- Detection status and type (`visual_text` vs `spoken_dialogue`)
- Exact `timestamp` and mathematically/visually derived `frame_number`
- The `tool_used` to find the match (`subtitle`, `whisper`, `ocr`, or `whisper, ocr` for fusion)
- A snapshot image of the frame (if visually matched)

6. Optimizations
----------------
- Network Efficiency: Entire 10GB videos do not need to be downloaded if the dialogue is found in subtitles or audio. Targeted `-ss` segment downloading saves massive amounts of bandwidth.
- Coarse-to-fine OCR: Full-video OCR is a last resort and is performed at 1 FPS. Fine OCR is only performed on ~120 frames during targeted refinement.
- Local GPU processing: `faster-whisper` and `EasyOCR` leverage CUDA for maximum local performance.
